# docs-structure v1.2.5 - check_my_security_prepare_level.md 廃止とデッドリンク削除

>
> このノートに記載する情報について:
> - API キー・パスワード・トークンは必ずプレースホルダー(`YOUR_API_KEY`等)で記載
> - 実際の機密情報は絶対に含めない

**作成日**: 2026-09-22
**関連タスク**: docs-structure v1.2.5 リリース

## 問題

`check_my_security_prepare_level.md` は docs-structure の actions の一つとして「セキュリティ準備レベル（Level 0/1/2）」を診断するアクションだったが、あまり使われておらず、セキュリティチェック側（setup-securecheck）で独立して対応したいというユーザーの意向があった。

また、v1.2.4の観測作業で `patterns/setup-pattern/README.md` の「関連パターン」に、v1.2.0で既に廃止済みの `patterns/actions-pattern/` へのデッドリンクが残っていることも判明していた。

## 調査

`check_my_security_prepare_level.md` の中身を確認したところ、診断ロジックが以下の点で実態と乖離していた:

- husky pre-commit の存在確認を前提にしているが、setup-securecheck は v2.0.0 で husky+lint-staged から simple-git-hooks へ移行済み
- v3.0.0（`.security-check/`集約・フェイルクローズ・毎コミット自動カナリア自己検証）以降の設計変更にも追従できていない
- setup-securecheck 自身がバージョン検出・自己検証の仕組みを持つようになったため、docs-structure 側の簡易診断（Level 0/1/2モデル）は機能的に重複していた

参照箇所を洗い出した結果、実ファイルは `templates/actions/`（ja/en）と本リポジトリの `docs/actions/` に存在し、以下から参照されていた:
- `templates/actions/help.md`, `templates/actions/README.md`（ja/en、`docs/actions/`含む）
- `patterns/setup-pattern/docs-structure-for-branch/for_branch_init.md`（ブランチ初期化時の書き換え対象ファイル一覧、完了通知テンプレート）
  - `for_branch_init.md` 側は `fs.existsSync` ガードがあり、ファイルが存在しなくてもエラーにはならない設計だったが、廃止済みファイルへの参照を残すのは紛らわしいため合わせて削除

## 解決策

### 1. check_my_security_prepare_level.md の削除
- `patterns/docs-structure/templates/actions/check_my_security_prepare_level.md`
- `patterns/docs-structure-en/templates/actions/check_my_security_prepare_level.md`
- `docs/actions/check_my_security_prepare_level.md`（本リポジトリのデプロイ済みコピー）

### 2. 参照の削除
- `templates/actions/help.md`（ja/en）: 「🔒 セキュリティ・セットアップ系」セクションと使い分け表の行
- `templates/actions/README.md`（ja/en）: アクション一覧の該当行
- `docs/actions/help.md`, `docs/actions/README.md`: 同様
- `patterns/setup-pattern/docs-structure-for-branch/for_branch_init.md`: 書き換え対象ファイル配列・完了通知テンプレートから該当行を削除

### 3. actions-pattern デッドリンク削除
- `patterns/setup-pattern/README.md` の「🔗 関連パターン」から `../actions-pattern/` へのリンクを削除し、「docs-structure（actionsによるAIへの指示テンプレートを含む）」という説明に統合

### 4. VERSION / CHANGELOG
- `patterns/docs-structure/VERSION`, `patterns/docs-structure-en/VERSION` を 1.2.4 → 1.2.5
- CHANGELOG.md（ja/en）に「### 廃止」「### 修正」セクションを追加

## 学び

- 「機能を持つアクション」を廃止するときは、そのアクション自体の削除だけでなく、①一覧・ヘルプへの掲載、②他のアクション（今回は`for_branch_init.md`）からの参照、の2方向で影響範囲を洗い出す必要がある
- `existsSync` のようなガードがあるコードは実害が出ない場合でも、ドキュメント上の「廃止済みファイルへの言及」は読み手を混乱させるため、ガードの有無に関わらず参照は消すのが望ましい
- パターン内の機能重複（docs-structureの簡易セキュリティ診断 vs setup-securecheckの本格的な自己検証機構）は、各パターンが独立して進化すると自然に発生する。定期的な棚卸しの価値を再確認した

## 今後の改善案

- 同種の「別パターンとの機能重複」が今後も起こりうるため、パターン間の責務分担をREADME等に明記しておくと発見が早まるかもしれない
