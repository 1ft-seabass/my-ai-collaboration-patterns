# docs-structure v1.2.6 - GUIDE.md/SETUP.md廃止とREADME.mdのミニマム化

**作成日**: 2026-09-23
**関連タスク**: docs-structure v1.2.6リリース。[メンテナンスコストのアーキテクチャ方針合意](./2026-09-22-23-20-37-maintenance-cost-architecture-direction-agreement.md)で決めた「経緯システム側でミニマムな整えをやってみる」の実行編

## 問題

v1.2.4/v1.2.5の作業を通じて「同期漏れ型のバグ」が繰り返し見つかったため、`SETUP.md`/`GUIDE.md`/`README.md`/`TEMPLATE.md`という4種類のドキュメントファイルについて、実際にメンテナンスされている実感があるのはどれか、という素朴な疑問からリポジトリ全体を棚卸しした。

## 調査

`find`でリポジトリ全体のSETUP.md/GUIDE.md/README.md/TEMPLATE.mdの所在を洗い出し、それぞれが実際にどこから参照され、どのタイミングで読まれるかを追った。

- **SETUP.md**: リポジトリルートに1つだけ存在（`./SETUP.md`）。docs-structureパターン内には元々存在しない。中身はこのモノレポ自身の古い構造説明（`docs/ai-collaboration/`, `docs/letter/`（旧単数形）等、最終更新2025-10-23）で、ルートREADME.mdからも参照されておらず、どこからも到達しないファイルだった。`templates/README.md`内の`[SETUP.md](../SETUP.md)`リンクは、配布先プロジェクトでは確実にデッドリンクになる（本リポジトリではルートに同名ファイルがあったため偶然繋がって見えていただけ）
- **GUIDE.md**: `patterns/docs-structure(-en)/`のパターンルート直下にのみ存在し、`templates/`配下には含まれない＝**degitで配布されない**。「degit後に読む」と自称していたが、実際に使われる一次動線（パターンルートREADME.md冒頭の「AIへのワンショット指示」ブロック）はGUIDE.mdの取得・参照を一切要求しない設計だった。人間がGitHub上で能動的にクリックしない限り到達せず、事実上ほぼ読まれていなかった
- **README.md**: 階層によって扱いが分かれた。パターンルートREADME.mdの「AIへのワンショット指示」ブロックは実際に使われている一次情報源で健全だったが、同ファイルの「🔗 関連パターン」節は`server-management`, `prompt-engineering`という実在しないディレクトリへのデッドリンクが残っていた。配布先の`templates/README.md`（＝`docs/README.md`）は、存在しないaction名（`git_commit_and_push.md`等）や陳腐化した「フォルダ案内」節を抱えていた
- **TEMPLATE.md**: 各種actionから毎回明示的に読まれる実働テンプレートで、外部リンクをほとんど持たず自己完結的なため、最も健全だった

さらに、`docs/actions/*.md`を全件grepした結果、運用中（セッション開始〜終了のループ）で`docs/README.md`を参照するアクションが1つも無いことも確認した。実際の「次セッションの入口」は申し送り完了通知が直接指定する個別の申し送りファイルであり、`docs/README.md`は「セットアップ直後に人間が一度だけ開く着地ページ」という位置づけに留まることが分かった。

## 解決策

### 1. GUIDE.md（ja/en）を廃止

実質誰にも読まれておらず、内容も陳腐化していたため削除。参照元（パターンルートREADME.mdの「詳細ドキュメント」節、`templates/actions/README.md`の「詳細ドキュメント」節、`docs/actions/README.md`）からもリンクを削除。ルートREADME.mdにも3箇所GUIDE.mdへの言及があり、これも合わせて修正（README.mdに一本化する形の文言に変更）。

### 2. SETUP.md（ルート）を廃止

docs-structureパターンと無関係かつどこからも参照されていなかったため削除。

### 3. `templates/README.md`（ja/en、配布先`docs/README.md`）のミニマム化

- 存在しないaction名の記載を、実在ファイル名（`01_git_push.md`, `doc_letter.md`, `start_init_rule.md`）または`actions/README.md`への参照に修正
- 陳腐化した「必要に応じて追加できるフォルダ」節（`ai-collaboration/`, `architecture/`, `development/`, `spec/`）を削除。この節は、同ファイル内で「READMEの手動一覧は更新漏れのリスクがある」と自ら述べている方針と矛盾していた（自己矛盾の発見が削除の決め手になった）
- 廃止した`SETUP.md`へのデッドリンクを削除

### 4. `patterns/docs-structure/README.md`のデッドリンク削除

「関連パターン」節から`server-management`/`prompt-engineering`（実在しないディレクトリ）へのリンクを削除。

## 学び

- 「実行される指示文（ワンショット指示ブロック、TEMPLATE.md）」と「読み物・周辺リンク（GUIDE.md、README.mdの関連リンク集、SETUP.mdへの参照）」とで、健全さがくっきり分かれた。境界線は「AIが毎回強制的に読む経路にあるか、人間が能動的にクリックしないと辿り着かないか」
- ファイル自身が「手動一覧はメンテ漏れするから持つな」と主張しながら、まさにメンテ漏れした手動一覧を掲げているという自己矛盾は、削除の判断根拠として説得力が強かった。今後同様の陳腐化を疑う際、「このファイルが自ら掲げている原則と、このファイル自身の中身が矛盾していないか」を確認する視点は使える
- `docs/README.md`は「セットアップ直後の一度きりの着地ページ」という限定的な役割に留まることが判明した。今後もこの位置づけを踏まえ、運用ループに関わる情報（action名など）の正確性は保ちつつ、それ以上の情報を持たせすぎない（カタログ化しない）方針を維持する
