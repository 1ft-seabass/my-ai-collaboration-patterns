# 引き継ぎメッセージの運用ルールで「作業継続」と「コミット」の確認を分離 - 開発記録

> **⚠️ 機密情報保護ルール**
>
> このノートに記載する情報について:
> - API キー・パスワード・トークンは必ずプレースホルダー(`YOUR_API_KEY`等)で記載
> - 実際の機密情報は絶対に含めない
> - .env や設定ファイルの内容をそのまま転記しない

**作成日**: 2026-08-22
**関連タスク**: docs-structure パターンのテンプレート改善（ユーザーからのフィードバック対応）

## 問題

`00_session_end.md` / `doc_letter.md` が生成する引き継ぎメッセージ内の運用ルールに、以下の一文があった。

> 不用意なコミットはせず作業を進めましょう。それでもコミットせざるえない場合は必ずユーザーにコミット予定を伝え承諾をとってください。

ユーザーから、この運用ルールのもとでAIが「（作業を）進めていいですか？」と尋ねた際、それが「作業の続行」の確認なのか「コミットの実行」の確認なのかが文面上区別しづらく、ユーザーが「はい！」と一言で答えるとどちらに同意したか事故りやすい、という指摘があった。加えて、コミットのタイミングは通常ユーザー側が明示的に指示することが多いという運用実態も、ルール文に反映されていなかった。

## 解決策

引き継ぎメッセージ内の運用ルールを、「作業を進めていいですか？」と「コミットを進めていいですか？」を必ず分けて質問する形に書き換えた。

**実装場所**:
- `patterns/docs-structure/templates/actions/00_session_end.md:113`
- `patterns/docs-structure/templates/actions/doc_letter.md:64`
- `patterns/docs-structure-en/templates/actions/00_session_end.md:113`
- `patterns/docs-structure-en/templates/actions/doc_letter.md:64`
- 上記テンプレートに対応する、このリポジトリ自身の dogfood コピー `docs/actions/00_session_end.md` / `docs/actions/doc_letter.md`

日本語版の修正後の文言:

```
不用意なコミットはせず作業を進めましょう。コミットが必要な場合は「作業を進めていいですか？」と「コミットを進めていいですか？」を必ず分けて質問し、ユーザーの承諾を得てから実行してください（コミットのタイミングは通常ユーザーが明示的に指示します）。
```

**主なポイント**:
1. `templates/` 配下（配布用テンプレート）と `docs/actions/` 配下（このリポジトリ自身が使っている dogfood コピー）は元々内容が完全一致していたため、両方に同一の修正を反映し一致を維持した
2. 日本語版・英語版（`docs-structure` / `docs-structure-en`）で同じ趣旨の修正を行った
3. 運用ルールの変更のため、`docs-structure` / `docs-structure-en` のバージョンを `1.2.2` → `1.2.3` に上げ、両 CHANGELOG に追記した

## 学び

- 引き継ぎメッセージに埋め込む運用ルールは、次セッションのAIの質問の仕方（フレーズそのもの）まで指定しないと、実際の対話で意図しない省略・混同が起きうる
- 「はい」で両方の意味に取れる質問文は、ユーザー側の同意粒度を曖昧にするリスクがある。承認を要する行為が複数ある場合は、質問自体を行為ごとに分離するようテンプレート側で明示するのが効果的
