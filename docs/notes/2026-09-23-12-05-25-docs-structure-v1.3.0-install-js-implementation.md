## 問題

v1.2.6までで「経緯システム側でミニマムな整えをやってみる」（GUIDE.md/SETUP.md廃止、README.mdのミニマム化）は完了していたが、これはドキュメントの削除・整理であり、方針合意ノートが本来求めていた「実際にNode.jsの決定的コードを書く」というタスクにはまだ着手していなかった。構想合流ノートの「次の一手」がsetup-securecheck側の`setup-local`を指していたが、[構想合流ノートのToDo突き合わせ漏れ](./2026-09-23-01-38-53-confluence-note-todo-crossref-gap.md)で判明した通り、実際の起点はこちら（docs-structure単体のインストーラー）だった。

## 調査・設計判断

### 参考にしたもの・しなかったもの

`patterns/setup-pattern/docs-structure-and-securitycheck/setup-all.js`の`copyRecursiveSkipExisting()`（既存ファイルはスキップし、無いものだけ差分で補完するアルゴリズム）を参考にした。ただし`setup-all.js`自体は密結合ゆえに廃止・疎結合化の検討対象になっているパターンであり、その周辺の前提（package.json必須化・`npm init -y`・git init・`.security-check/logs/`へのログ出力）まで軸にするのは誤りだと気づいた（[docs-structure/setup-securecheckの概念腑分け](./2026-09-23-08-57-31-docs-structure-securecheck-concept-breakdown.md)参照）。install.jsはこれらを一切持ち込まず、`copyRecursiveSkipExisting`のアルゴリズムだけを流用した。

`patterns/setup-pattern/docs-structure-for-branch/for_branch_init.md`の`node -e`埋め込み方式も確認したが、こちらは方針合意ノートで既に「今後使わない旧方式」と決着済みのため、独立スクリプトファイル方式（setup-all.js方式）を採用した。

### cwd安全確認の設計

setup-securecheckの`cli.js`が持つ`assertRunFromProjectRoot()`（`__filename`の実際の場所と`process.cwd()+'.security-check'`を比較するcwdガード）を転用しようとしたが、これは「`.security-check/cli.js`という永続的にインストールされた既知の相対位置にあるファイル」という前提に依存しており、一時的に取得されて1回実行されたら消えるinstall.jsには比較対象となる「あるべき相対位置」自体が存在しないため転用できないと判明した。代わりに、何かを書く前に配置先の絶対パスを目立つ形で出力する、という別の安全策を採用した（[Node要否・実行主体・判断主体の地図ノート](./2026-09-23-11-36-46-runtime-executor-judgment-axes-map.md)で整理した「AI実行主体特有の揺れ」への対処）。

## 解決策

### 1. `install.js`の新設（ja/en）

- `patterns/docs-structure/install.js`、`patterns/docs-structure-en/install.js`
- コピー元は`__dirname/templates`（degitで自分と一緒に取得されたもの）、コピー先は`process.cwd()/docs`
- 何かを書く前にコピー元・配置先の絶対パスを出力
- `copyRecursiveSkipExisting`相当で差分コピー（既存ファイルは絶対に上書きしない）
- 作成0件かつ実行前から`docs/`が存在していた場合は、「既存のdocs-structureを最新版に更新する場合」の判断層ウィザードへ誘導するメッセージを表示
- package.json/git initには一切依存しない
- en版はコンソール出力も含めて全て英語で独立に用意（ja/enはミラー関係のため）

実機で以下4パターンを検証済み:
- 新規（`docs/`が存在しない）→ 20ファイル作成
- 中断からの再開（`docs/letters/README.md`のみ既存）→ 既存ファイルを上書きせず、不足していた19ファイルを補完
- 既存フル導入（2回目実行）→ 全件スキップし、判断層ウィザードへの誘導メッセージを表示
- `templates/`が隣に無い状態 → 分かりやすいエラーメッセージでexit 1

### 2. README.md（ja/en）の再構成

冒頭のワンショット指示を、以下の5スロットに再構成した。

- **新規プロジェクトへの導入**: 1. Node.js前提でのAIワンショット指示書（install.js経路、新規）／2. プロンプトのみで動くAIワンショット指示書（既存の`npx degit`直接指示を流用）／3. 手動で行う場合の手順（既存の`git clone`+`cp -r`を流用）
- **既存プロジェクトの更新**: 1. プロンプトのみで動くAIワンショット指示書（既存の「既存のdocs-structureを最新版に更新する場合」ブロックをそのまま維持。完成度が高いため無改変）／2. 手動で行う場合の手順（`diff -r`による差分確認手順を新規追加）

あわせて、内容が重複していた「🚀 使い方」節（`degit で取得`・`Git Clone`・`AIに読ませる`）を削除した（`AIに読ませる`は「🎯 使用例」節の「セッション開始時」と完全重複していた）。

### 3. VERSION / CHANGELOG

`patterns/docs-structure/VERSION`, `patterns/docs-structure-en/VERSION`を1.2.6→1.3.0に更新（[kit構想 Fableセッション原資](./2026-09-22-23-36-08-kit-vision-fable-session-source.md)の時間軸手順表で元々「1.2.3→1.3.0」と予定されていたバージョン）。CHANGELOG.md（ja/en）に追加・変更内容を記録。

## 学び

- 今回の設計プロセスは、直前に作成した2本の構想ノート（[概念腑分け](./2026-09-23-08-57-31-docs-structure-securecheck-concept-breakdown.md)、[Node要否・実行主体・判断主体の地図](./2026-09-23-11-36-46-runtime-executor-judgment-axes-map.md)）で整理した理論が、そのまま実装判断に落ちた実例になった。「setup-all.jsを参考にしてよい部分・してはいけない部分」「cwdガードが転用できない理由」は、事前に概念整理をしていなければその場で毎回考え直す羽目になっていたはず
- 「新規」と「既存への安全マージ」を同じ`copyRecursiveSkipExisting`ロジックで自然にカバーできる、という設計上の見立ては、実機検証でも4パターンとも想定通りに動作し、裏付けられた
- README.mdの「既存のdocs-structureを最新版に更新する場合」ブロックは、今回一切手を加えなかった。完成度が高い判断層ウィザードは、確定的な仕組み（install.js）を足すからといって巻き込んで書き直す必要はない、という線引きが実際に機能した
