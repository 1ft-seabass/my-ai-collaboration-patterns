# セッション運用ルール初期化アクション

セッション開始時に、このプロジェクトの運用ルールを確認・共有します。ノールールのまま作業を始めて事故るのを防ぐためのアクションです。

## 実行手順

1. `git log --oneline -10` で、このリポジトリのコミットスタイルを確認する
   - コミットメッセージのプレフィックス（feat:/fix:/docs: など）
   - 日本語 or 英語
   - AI 署名の有無（`Co-Authored-By: Claude` があるか）

2. 確認した内容を踏まえ、以下の運用ルールをそのまま提示する（コミットルールの具体値は手順1の結果で埋める）：

```
このプロジェクトのセッション運用ルール

・知見は docs/notes/ (命名: yyyy-mm-dd-hh-mm-ss-{title}.md、作成時 README/TEMPLATE参照) ※注意: ノート作成はユーザーが明示的に指示したときのみ実行すること
・申し送りは docs/letters/ (このファイル、作成時 README/TEMPLATE参照) ※注意: 申し送り作成はユーザーが明示的に指示したときのみ実行すること
・コミット: 従来のコミットログ（git log）を参考に、AI 署名の有無・プレフィックス（feat:/fix:/docs:など）・言語を統一すること
・不用意なコミットはせず作業を進めましょう。それでもコミットせざるをえない場合は必ずユーザーにコミット予定を伝え承諾をとってください。
・プッシュはせずコミットのみ(人間がレビュー後にプッシュ)

以下がコミットルールです。

プレフィックス: {手順1で確認した値}
言語: {手順1で確認した値}
AI署名: {手順1で確認した値}
```

3. ユーザーに内容の確認を求める（違いがあれば訂正してもらう）
4. 以降のセッションはこのルールに従って進める（毎回このアクションを呼び直す必要はない）

## 使いどころ

- 新しいセッションの冒頭、まだ運用ルールを共有していない状態で
- `00_session_end.md` が「終了時」の締めくくりなら、これは「開始時」の入口
